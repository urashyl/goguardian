Browsing Telemetry, Screenshots, about:blank & Device Profiling

How GoGuardian tracks tabs, iframes, viewport dimensions, visible pixels, hardware specs, installed extensions, and even user display names inside Manifest V3.

1. Tab & Browsing Activity (Zephyr /v1/entities) 60s / 1s flush

GoGuardian maintains an in-memory and LevelDB-backed Redux store tracking every open browser window and tab. Updates are batched and uploaded via WriteEntitySet every 60 seconds under normal monitoring, or every 1 second when a teacher enables increased flush rate during a live session.

  • Tab metadata: Tab ID, normalized URL (up to 131,072 chars), page title, favicon URL, active state, window isFocused state, and startTimeMs/endTimeMs viewing intervals.
  • User idle tracking: Queries chrome.idle to attach currentState (active / idle / locked) and durationMs.
  • Iframe metadata (goguardian-20.js): Injects into all frames and reports frame dimensions (width, height), visible status, and iframe title back to the service worker.
  • Viewport & scroll telemetry (goguardian-14.js): Reports scrollX, scrollY, windowWidth, windowHeight, and devicePixelRatio to align screenshots and live teacher annotations.

2. Screenshots & How about:blank + Iframes Are Handled goguardian-21.js

All standard screenshots pass through a single helper in background.js ([lib/screenshot]), which branches depending on whether the active tab URL starts with about:blank: 

activeTab = chrome.tabs.query({ active: true, windowId })
if (!url.startsWith("about:blank")):
    capture via chrome.tabs.captureVisibleTab(windowId, { format: "jpeg"|"webp", quality })
else:
    if top-frame origin matches ERP exclusion (*://*.erplinq.com/* or *://esd.eschooldata.com/*):
        skip screenshot
    else:
        dynamically inject goguardian-21.js into frameIds: [0]
        render document.body with html2canvas-pro (7s timeout) -> JPEG/PNG dataUrl

What Shows Up Visually

  • Regular pages: Pixel-accurate JPEG/WebP capture of the visible browser viewport via captureVisibleTab.
  • Direct about:blank DOM: Visible—goguardian-21.js (not listed in manifest.json, injected dynamically via chrome.scripting.executeScript) draws document.body using html2canvas-pro.
  • Same-origin <iframe> in about:blank: Visible—rendered into the canvas when contentDocument.body has child nodes.
  • Cross-origin <iframe> in about:blank: Skipped visually—Same-Origin Policy blocks contentDocument access, so goguardian-21.js tags the frame with data-html2canvas-ignore="true". (Note: Teacher video-call screen sharing in video-call.js uses getDisplayMedia, which captures raw display pixels regardless of iframes.)

What Still Gets Logged Behind the Scenes

  • submitAboutBlankIframes: Inside shared/tabs/refreshTabs, whenever a tab is about:blank, GoGuardian calls chrome.webNavigation.getAllFrames({ tabId }).
  • For every subframe (frameId !== 0) with a non-about:blank URL, it queries Panther (/api/v2/categories) for the embedded URL's categories.
  • It records { url, categoryIds, frameId } on the tab entity and uploads it to Zephyr /v1/entities.
  • Content scripts with "all_frames": true and "match_about_blank": true still inject inside the embedded iframe's origin to collect text, flagged terms, and YouTube/image telemetry.

3. Webcam / Camera Previews & Background-Tab Screenshots captureVisibleTab

  • Does NOT secretly turn on the webcam: background.js contains zero getUserMedia or mediaDevices calls. Camera/microphone access only exists inside video-call.js and presentation.js (Twilio WebRTC) when participating in an explicit GoGuardian Teacher call or presentation with browser permission granted.
  • Web-based camera previews ARE captured in screenshots: Because chrome.tabs.captureVisibleTab() captures rendered pixels of the active http:///https:// tab, viewing yourself in any browser-based camera feed (e.g., Google Meet/Zoom web preview, webcam test site, online photo booth, Flipgrid/Canva recorder) places the live <video> frame—including your face and room—into Teacher live screenshots (every 3s), periodic activity snapshots, and Smart Alerts/Beacon screenshots.
  • Native ChromeOS Camera app (chrome://camera-app): Chrome blocks extensions from calling captureVisibleTab() on privileged chrome:// and chrome-untrusted:// pages (handled in background.js as [lib/screenshot] failed to capture tab), so the built-in ChromeOS Camera System Web App is not captured via captureVisibleTab.
  • Background-tab focus-switching for Smart Alerts ([lib/screenshot]): For Smart Alerts reports (admin/smart-alerts/report), if a flagged tab is in the background, background.js temporarily activates that tab via chrome.tabs.update(tabId, { active: true }), takes the screenshot, and immediately restores the previously active tab.

4. Device Identity, Hardware & Extension Auditing

  • Managed Device Detection: Calls chrome.enterprise.deviceAttributes.getDirectoryDeviceId(). On enrolled ChromeOS devices this returns the managed directory ID; on unmanaged devices or VMs it falls back to a persisted self-generated:<uuid>.
  • Installed Extensions Inventory: Reads chrome.management.getAll() and listens to onInstalled / onEnabled / onUninstalled. Uploads extension IDs, names, descriptions, types, and homepage URLs via SyncInstalledExtensions.
  • Active Extension Disabling: Checks installed extensions against adminSettings.apps.filters (and apps.safeMode) and disables disallowed extensions via chrome.management.setEnabled(id, false) when permitted.
  • Hardware Info: Collects archName and modelName via chrome.system.cpu.getInfo() plus capacity / availableCapacity via chrome.system.memory.getInfo().
  • Windows Native Host: On Windows deployments, connects via chrome.runtime.connectNative("chromium.goguardian.ggwindows") for OS-level app window tracking.

5. MV3 Offscreen Scraping & Anti-Tamper Watchdog

  • Display Name Scraping (offscreen-document.js): Because Manifest V3 service workers have no DOMParser, GoGuardian spins up a hidden offscreen document to parse fetched HTML from accounts.google.com/AccountChooser and myaccount.google.com (.XY0ASe "Welcome, <Name>") to resolve the student's display name (cached 24 hours).
  • Safe Inert Parsing: DOMParser.parseFromString(..., "text/html") is inert (scripts do not execute), only .textContent is read, and all errors are caught safely—so unusual display names cannot crash or disable the extension.
  • 25-Second Health Check: Every 25 seconds ([lib/content-script-health-check]), the service worker pings content scripts across all open http, https, about:blank, and (if allowed) file:// tabs to detect unresponsive or missing scripts.
  • Local Persistence: Stores buffered screenshots, BSON-encoded Redux state (store), and entity queues in Chrome's Local Extension Settings LevelDB.
